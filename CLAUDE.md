# AI Video Factory: project notes for Claude

Plan and architecture: `docs/PROJE_PLANI.md` (Turkish). Before changing a major decision, read the relevant section there and update it if needed.
The README is English (`README.md`) with a Turkish copy (`README-TR.md`): when you change one, update the other. CHANGELOG and release notes are English. This file is English.

## Structure
- pnpm workspace, TypeScript 7, ESM, no build step (tsx/vitest run from source). Packages export `exports: ./src/index.ts`.
- Relative imports carry the `.ts` extension (`./router.ts`).
- `packages/core`: shared Zod schemas. Money is **integer micro-dollars** everywhere (`usd()`, `formatUsd()`).
- `packages/media-gateway`: every generation call goes through here. Pipeline code never calls a provider directly.
- Providers are written as REST over `fetch` (no SDKs). Use `ctx.fetch` so tests can mock it.

- `packages/agents`: Agent SDK `query()` + `outputFormat: json_schema`. Schemas are converted to draft-07 with `toOutputSchema()` (Claude Code rejects 2020-12). Agent instructions are English; narration is in the episode language.
- `packages/pipeline`: stages are idempotent; `save()` after every sub-step. When adding a stage, think about the `STAGES` order and what `from` deletes.
- `packages/video`: Remotion; assets are read with `staticFile()` from the render folder's `public/` directory. Vector scenes (`Vector.tsx`) embed model-made SVG: every SVG is cleaned with `sanitizeSvg()`, repeating motion lives in code (no tokens spent). Render temp files go to `.render-tmp` next to the output instead of the system Temp; on a temp-file/browser error `renderEpisode` retries once from the start. Only one Remotion job per machine at a time (`withRenderLock`, render + still extraction): when two episodes rendered at once, one died with a Chrome crash.
- Motion physics `packages/video/src/motion.ts`: before render, the director's animations are made physical with `physicalAnims` (things on the floor don't float or move vertically, objects don't gesture, a held object doesn't move on its own, no sitting without a seat); walk steps are counted from the distance covered (`gaitOf`, feet don't slide), slow walks are shortened to natural speed (`paceWalks`). `PlacedLayer.grounded` comes from the layout. Gestures ease in over seconds (`gestureWeight`: anticipation, overshoot, forearm lag); point reaches for its target (`target`, or the nearest thing beside). Optional wrist parts `hand-l`/`hand-r` (inside the forearm, pivot in RIG; without them the pose has no effect): follow the forearm when idle, curl when waving, palm turns when explaining, a hand holding an object stays straight. A talking (`talk`) character's mouth moves syllable by syllable with the narration's word timings (`mouthOpen`; `Timeline.speech` is filled even with captions off, old timelines use a fixed rhythm). Torso, arms and head are wrapped into one group at render (`wrapTorso`; sibling groups in the drawing) and bend together from the hip (`torso` pose: weight shift when idle, toward the direction of travel when walking, toward the listener when explaining, toward the target when pointing, back when surprised; a held object follows). A character with an object in the right hand holds it to the side at chest height (`HOLD_POSE`) and makes spontaneous gestures with the left hand. On-screen text (`layoutTexts`): styles other than label go in a fixed info card at the top-left (the director's x/y is ignored); a label has one size and sits above a person's head: the character whose name appears in the label (`namesMatch`, the name in the quality-gate record), otherwise the head nearest the director's point; it moves with the camera and with walking (`cameraPoint`); the label of a character not in the shot or whose face is out of frame (`faceOnScreen`) is hidden (filtered before the two-text limit, takes no slot; the director is told the card and labels count together). A label only drops below a card/label it overlaps horizontally (two people side by side keep their labels on their own heads). Captions: render always writes `<id>.srt`; if `input.captions === false` they are not burned in (`onScreen`; draft/review stills are also caption-free, the inspector is told there are no captions and the `text_on_subtitles` defect is dropped; Studio `set-captions` reopens only the render). In a close-up, if the subject is smaller than 20% of the frame, `closeUpCamera` zooms in and centres; a surface with things on it (a desk) is never the subject, objects on the same surface are framed together (`PlacedLayer.on`); other objects visible in the director's framing stay in frame, and even when the subject is big enough, focus shifts / zoom drops for an object that doesn't fit (a screen cut off at the bottom, an overflowing magazine) (`fitWhole`; a character may be cut on purpose). In a close-up a held object or one placed on a desk becomes the subject before the person (size is the square root of area, target 40% of the frame; the holder's head stays in frame, the face is never cut; so does the head of a person standing beside / at the desk of the object); the camera takes the held object's position from the hand in the holding pose (`heldFraming`). A wall/air item more than half covered by furniture is moved in front of that furniture (`resolveLayout`). In a static wide shot, if the content fills only a small part of the frame, `fillWide` moves in to a medium shot (at most 1.8; a person may be cut at the knees, furniture with something on it or someone sitting on it at half height, other objects stay whole and above the caption band; not when something walks or slides); if moving in isn't worth it but the content is piled to one side (more than 15% of the frame width from the director's view centre), it is recentred at the director's zoom, but not with a panning camera (panX). In a wide shot (zoom 1–1.5) `frameWide` keeps characters with their heads and small objects in frame (except those entering): panning is dropped, focus shifts, zoom drops if needed. A character appears at most once per shot (`uniqueCharacters`: duplicates are dropped in the plan and at render); when a layer is dropped, index references (`on`, `heldBy`, point `target`) are remapped with `keepLayers`. Side view (`input.sideViews`, off by default): characters that move get a second drawing facing right per `RIG_SIDE` (`vectorSideViews`; the gate compares it with the front drawing, key `<front>.side.svg`), `<id>~side` in the timeline; render turns to it while walking.
- Atmosphere (`Ambience.tsx`): particle kinds (rain + splashes, snow, dust, embers, confetti) use PixiJS/WebGL (`PixiParticles`, `particles.ts`): the Pixi ticker is off, every frame is computed statelessly from `particleFrame(kind, seed, t)` and rendered by hand (parallel tabs get the same frame); `delayRender` until Pixi is ready; if WebGL can't start the layer stays empty and the render doesn't fail. Fog, flicker and light rays are CSS gradients. `pixi.js` is faked in tests.
- Globe maps (`projection: "globe"`) are 3D with three.js (`Globe3D.tsx`, maths in `globe.ts`): `generateMap` returns `meta.globe` next to the SVG (centre/radius of the orthographic projection + an equirectangular 4096×2048 texture SVG, sanitized). The orthographic camera gives the same image as d3's projection: the globe rotates in during the first 25% of the shot (`globeView`), and once it stops the SVG's routes/markers and labels sit exactly on it (the SVG base group `globe-base` is hidden; `MapOverlay` plays with `overlayProgress`). three has no loop, every frame is rendered by hand; `delayRender` until the texture loads, empty layer without WebGL. Old globes without `meta.globe` stay SVG. `three` is faked in tests (`globe3d.test.tsx`); rotation maths is tested with real three (`globe-math.test.ts`).
- `draw_on` layer animation (`drawOn.ts`): the object appears as if drawn by hand. `drawPlan` marks drawable elements (except those inside `defs`/`clipPath`/`mask`…) with `data-draw` and measures their lengths from path data with paper.js (`paper/dist/paper-core`; `importSVG` is not used, it needs an iframe); strokes are drawn in document order in time proportional to length (80% of the progress), fills follow, elements without a stroke get a temporary ink line. `drawCss` only produces CSS each frame and writes no rule for finished elements (original look; `pathLength` is not used so dashed lines in the design survive). Broken path data has length 0: the element appears whole when its turn comes.
- `kinetic` text animation (`kinetic.tsx`, GSAP): the plate wipes open from the left, words rise one by one in masked boxes. The GSAP timeline is paused and its own clock is not used; `progress(q)` every frame (parallel tabs get the same frame). When the animation ends, `revert()` removes the inline styles. HyperFrames was not adopted because it is a separate render engine (user decision, 2 Nov): its animation engine, GSAP, runs directly inside Remotion. Real GSAP in tests (happy-dom).
- Manim board (`pipeline/src/manim.ts`): the director gives a shot a `math` recipe (LaTeX steps + a line/bar graph with data points); in the timeline stage (`mathBoards`, vector only) code writes the Manim script from the recipe and local Manim renders a transparent WebM (`MATH_BOARD` 1040×560, key `library/math/<recipe+duration+colour hash>.webm`, `MATH_VERSION`). The model's code never runs; LaTeX passes the `safeLatex` allow-list (ASCII, allowed commands, no `^^`/`%`/`#`/`$`), texts are embedded as JSON strings. If Manim is missing or fails, the shot goes on without a board. `overlay` in the timeline; Episode plays it in the `MathBoard` panel (fixed to the screen, centred). Render and draft stills copy the clip to `public/`. Location: `YS_MANIM`, `YS_LATEX_BIN`, or `.data/tools/manim-venv` + MiKTeX (README). The Manim call is faked in tests (`BoardRun`).
- Sound effects (`video/src/sfx.ts`, `@ys/video/sfx`): in the timeline stage (vector, `input.sfx !== false`) events are derived from the animations with the render's timings (kinetic word landing shares `kinetic-timing.ts` with GSAP, typewriter letters, counter ticks + bell, pop, slide_in/spin whoosh, draw_on pencil, Manim board); sounds are synthesized in code (seeded noise/sine, no API), mixed into one 24 kHz mono WAV track (`assets/sfx/<episode>/<hash>.wav`) and added as the `sfx` audio. Studio: switch in the new-episode form (vector only) and the overview; `setSfx` reopens the timeline and render (free). If animation timing changes, update the event extraction too. Idea from the kalem repo (frame-locked events).
- Background music (`video/src/music.ts`, `@ys/video/music`): synthesized in code in the timeline stage (every mode, `input.music !== false`), no API. Sections come from the shots' `vector.mood` (`musicSections`: consecutive shots with the same mood form one section, one shorter than 8 s joins its neighbour; non-vector shots are neutral); mood → tempo/chords/arpeggio/bass in `FEEL`; all sections share one key (major + relative minor, key chosen from the episode id), transitions are 2 s equal-power crossfades. Ducking is baked into the track (`speechRegions`: `speech`, else captions, else the voice tracks; short silences are bridged). Levels live in `MUSIC` (−25 dBFS between lines, −11 dB under narration; TTS measured at ~−16.5 dBFS); the render's loudnorm brings the final mix to −14 LUFS. One 24 kHz mono WAV (`assets/music/<episode>/<hash>.wav`), `music` audio, volume 1. Studio: switch in the form and the overview, `setMusic` reopens the timeline and render (free). Tests compare tracks as bytes (`toEqual` is very slow on big arrays).
- Vertical video (9:16) safe zone `VERTICAL_SAFE` (core/rules.ts: top 250, bottom 420, right 150 px; Shorts/Reels UI): captions sit above the bottom UI and away from the buttons on the right, name tags stay in the visible part of the canvas outside the button strip (`tagBounds`), the Manim board is scaled like the stage (`stageFit`, same formula for stage and board). Idea from the kalem repo.
- Publishing package (`package` stage, between render and review): the `packager` agent (fast tier, episode language) writes the YouTube title, thumbnail text, description, chapters (by scene id), tags and hashtags. Chapter times are computed in code from `sceneOffsets` (`chapterLines`: YouTube's rule, first at 0:00, at least 10 s apart, none if fewer than 3). `<episode>.youtube.txt` is written; `state.package` can be copied from the Studio overview. If the agent fails, the thumbnail is still drawn.
- Vertical Short (`short` stage, between package and review; `pipeline/src/short.ts`): the packager's `short` ({from, to, title}: consecutive scenes, inclusive) picks the range, the agent sees each scene's length (`sceneSec`). `shortRange` enforces the limits in code (over `SHORT.maxSec` 60 trims from the end, under 15 s extends forward without passing 60, a single long scene up to YouTube's 180 s; no or unknown pick → from the start). `shortTimeline` cuts visuals/voice/words to the range, 1080×1920, drops music/sfx; the stage regenerates them for the clip, copies the new audio into the render `public/` and renders `<episode>.short.mp4` (`state.short`). Skipped for vertical episodes and `input.short === false`; errors don't fail the stage. Toggling captions/sfx/music reopens `short` too; `setShort` reopens only `short`. Studio: player, download (`?short`), title in the package card. In vertical frames `contentFit` shrinks the stage per wide shot so kept characters/props are not cut (not for close-ups, maps or Manim boards); `tagBounds` takes that fit.
- Thumbnail (`video/src/thumbnail.ts`, `Thumbnail.tsx`, composition "Thumbnail" 1280×720): `<episode>.jpg` in the publishing package stage (`state.render.thumbnail`; a re-render keeps the record, the thumbnail stays valid unless the package stage is reopened). Shot from `thumbnailShot`: a full vector scene with people and objects (maps rank lower, ties go to ~40% into the video), otherwise the middle still, none for clips only. Title is the package's `thumbnailText`, else `thumbnailTitle` (shortest meaningful part of a split title), never uppercased (the Turkish rule turned the English brand into "MİCROSOFT"); placed opposite the people, bottom centre if people are on both sides. The shot's own texts are not drawn. Errors don't fail the stage. Studio: video poster and download (`?thumb`).
- ffmpeg/ffprobe calls go through `runMediaTool` (`@ys/video/tools`): if they are not on PATH it falls back to Remotion's copy (when Studio was started from a terminal with an old PATH, voice-over failed with `spawn ffprobe ENOENT`); that copy has no fps filter, so clip normalization doesn't fall back and fails with a clear error.
- In the vector keyframes stage, while objects are being drawn, the still of a shot whose assets are all ready is extracted right away (`vectorPropsDraw(state, true)`, one sequential render chain, stops after the first error); an error that stops the stage does not preview that object's shot. The draft review / final preview refreshes them all.
- Studio jobs run as a CLI child process whose output is read from a pipe; the job must survive Studio closing: the CLI swallows broken pipes (EPIPE) (`apps/cli/src/pipes.ts`), otherwise it died silently at the first log line.
- Pipeline `this.log` lines are written to `state.activity` (last 400) and `heartbeatAt`; Studio reads episode status from the state file with `runStatusOf()` (jobs started from the CLI show too; no entry for 15 min means "stuck").
- `apps/studio` client components (`"use client"`) import only **types** from `@ys/pipeline/light`; runtime code reaches `node:fs` and Turbopack crashes. A server page can't call a plain function from a client file: shared helpers live in `src/lib/`.
- **Quality gate and realism are mandatory:** no SVG is used unchecked (`designAsset` → `gateCheck`: blind guess + `assetGate`, thresholds in `core/rules.ts`; the Studio Rules page shows the same constants). Real subjects and every object are drawn from images found online (Wikipedia/Commons) (`pipeline/src/reference.ts`). To change a threshold, change only `QUALITY_GATE`. Before drawing, `assetPlanner` looks at the references, fits the description to the asset type and writes a plan (`<key>.plan.json`, once); the designer draws to the plan, the gate looks for the plan's cues. The plan can't change the object's type (a magazine cover stays a magazine, the picture on the cover is drawn inside it); the original request also goes to the gate and type drift scores low (`gateDescription`). If the planner says the references don't show the subject (`referencesMatch: false`), the search is redone with its `betterQuery`; without a query, unrelated images are not sent to the designer or the gate.
- Real-world facts like maps and flags are never drawn by Claude: the director gives a `map`/`flag` recipe and `pipeline/src/geo.ts` builds it from real data. When adding a new "factual" asset type (logo, monument, building…), look for a real data source first.
- Style packs in `core/styles.ts` (`STYLE_PACKS`, at least 20; a test checks this): "auto" is chosen by `stylePicker`, "custom" is the old `artDirector`. Line style is `lineStyleOf(state)` (the pack's unless the user chose one). Approved characters have `identity` in their meta; `listLibraryCharacters` returns those in the same style + line style; casting reuses them with `reuse`, Studio with "Use from library" (`reuseCharacter`).
- Character bank (`pipeline/src/library.ts`): approved characters in the library (`identity`: `role`, `bank`, `mascotOf`). Bank drawing is `createBankCharacter` (virtual episode `CHARACTER_BANK_ID`, its state is not saved; Studio job is the `bank add` CLI). In an episode, `input.presenter`/`bankCast` + series mascots join the cast in the cast stage without redrawing (`addBankCast`; casting is told they are "already in the cast"); when an episode is created, `withBankChoice` sets the style pack and line style from the characters (vector only). The presenter goes to the director as `presenter`: in most shots, `talk` while narrating.
- Style samples (`pipeline/src/samples.ts`, index `library/style-samples.json`): one character and one room per pack for the gallery in the new-episode form (`style-gallery.tsx`, thumbnails via `/api/assets`, click selects the pack). `existingSamples` takes them free from episodes drawn in that pack (newest first, gate-passed or human-accepted, not rejected); `drawStyleSamples` (`ys styles samples [pack...]`) draws the missing ones with the same brief in every pack (`SAMPLE_BRIEF`): the character via `createBankCharacter` (joins the bank as presenter), the room via `designAsset` under the virtual episode `STYLE_SAMPLES_ID`. Complete packs are skipped, failures are logged and skipped, the index is written in sequence. Shared virtual state for bank/samples: `virtualState`.
- Series (`pipeline/src/series.ts`): `input.series`; "auto" style picking inherits the series' previous pack, the series' characters come first in the library. Series names are compared with `sameSeries` (case and whitespace insensitive).
- Agent models: every agent has a default tier in code; the user picks a model per agent in Studio → Models (`settings/models.json`, `core/models.ts` → `AGENT_ROLES`). When adding an agent, add it to `AGENT_ROLES` and to the Models page groups; the choice is applied in `runStructured` via `modelFor`.
- Version: the single source is the root `package.json`. `pnpm release [patch|minor|major] [--publish]` (main, clean tree, typecheck+test, CHANGELOG, tag; nothing leaves the machine without `--publish`). Studio shows an update notice when it sees a newer GitHub release (`YS_UPDATE_CHECK=0` turns it off). Without dev: `pnpm studio:build && pnpm studio:start`.
- Every agent call starts its own Claude Code child process: at most `YS_CLAUDE_CONCURRENCY` (default 4) run at once per process; if the child crashes (`process exited with code …`, 0xC0000409 on Windows), the API returns overload/rate limit/5xx or a network error (`is_error` + `api_error_status`; network errors have no status code and are recognised from the text), no result message arrives, or `YS_AGENT_TIMEOUT_MS` (default 10 min) passes, `runStructured` retries twice; the cost of failed attempts is added to the result. The model's own errors (turn limit, schema) are not retried. The child is isolated from the user's ~/.claude (`ISOLATION`: no setting sources, strict MCP, claude.ai connectors/plugins/skill sync/hooks off, auto memory off, `verbatimPrompts`). Text that changes from scene to scene (correction notes etc.) goes in the user prompt, not the system prompt (prefix cache).
- Quality-gate economics (31 Oct production data): an asset rejected in an episode is not redrawn automatically on resume/restart (a new drawing is a human decision: reject in Studio), and a rejected object is not offered to the director (`vectorProps[id].rejected`). A redraw builds on the previous attempt (`previous`), viewer guesses accumulate; if the first two attempts score below `QUALITY_GATE.hopelessAtMost`, no third is drawn. The gate is given the channel's style and palette (a colour the palette forces is not a defect). The draft review replans only the worst scenes (`DRAFT_REVIEW`). Expensive intermediate results survive a failed stage: `scriptDraft`, `shotPlanDraft` (with a fingerprint of their inputs; deleted when the stage finishes).
- Concept/asset flows are tested end to end with a fake Claude in `pipeline/test/concept-flow.test.ts` (each agent is recognised from the fields of the schema it asks for). When `designAsset`/`vectorConcept` change, add a scenario there.
- Run lock (`pipeline/src/lock.ts`): `pipeline.run` takes a per-episode lock (pid + machine); a second run is refused, a lock whose owner died is stale. Studio decides "is a job running" from the lock first.
- Wikimedia requests go through the queue in `reference.ts` (spacing + waiting on 429); the User-Agent carries the project address, not a personal email. Ready-made SVGs are taken only under public-domain/CC0 (no attribution required) licences.
- Studio API: write requests only from the same origin and as JSON (`apps/studio/src/proxy.ts`). Every action that changes episode state is refused while a job runs (`episodeBusy`: Studio job + state file); a running pipeline rewrites the state from memory and an interleaved change would be lost.
- The shared library (library/…) is never changed in place by one episode's decision: a human rejection draws to a new derived key, realism-off passes are marked with `fidelitySkipped`, rejecting a reused character only detaches it from that episode.
- When model SVG is sanitized, values containing `&`/`\`, external `url()` and `style` properties outside the allow-list are dropped; if you touch the sanitizer, add a bypass example to `packages/core/test/sanitize.test.ts`.
- `apps/studio`: UI strings come from the `src/lib/i18n.ts` dictionary (TR + EN, both required); never hard-code text in components.

## Versions
- Every dependency is at its latest version and pinned **exactly** (no `^`). Very new versions blocked by pnpm's minimumReleaseAge rule are listed in `pnpm-workspace.yaml` → `minimumReleaseAgeExclude`. Run integration tests on major version jumps (e.g. postgres 4).
- Docker: postgres 18.6, redis 8.10, rustfs 1.0.4. Ports 5433/6380/9000 so they don't clash with other projects.

## Rules
- **Cost first:** a new provider must have `price` and `qualityPrior`. Cite the price source in a comment. If there is a local (ComfyUI) option, prefer it.
- If you are not sure about an endpoint or field names, add the spec with `verified: false`.
- Code comments are Turkish; the Studio UI is Turkish + English (from the dictionary). Pipeline log lines and user-facing errors are written with `msg("log.…"/"err.…")` + `LocalizedError`, their texts live in the `core/src/messages/` catalogue (TR + EN required); Studio shows the selected language, the CLI prints Turkish. The Turkish template must stay identical to the old output (the `WARN` level looks at the Turkish text).
- After every change: `pnpm typecheck && pnpm test`. Test coverage is 100% (lines, branches, functions, statements; threshold in `vitest.config.ts`): new code comes with tests, and `pnpm test:coverage` fails if it drops. No real network/Claude/Chrome/ffmpeg in tests (fake `fetch`, `queryFn`, `vi.mock`). Studio client components are tested in `apps/studio/test/client` (happy-dom), the server side in `apps/studio/test/server`. `/* v8 ignore */` only for truly unreachable defensive code, with a reason; oxc drops comments inside a variable initializer, a parenthesized expression or an array element, so the hint has no effect there: put it on the line before the statement.
- The budget cap is only for paid image/audio/video APIs (`ledger.spent` doesn't count "llm" entries). Claude agent calls may exceed the cap (user decision, 30 Oct); their costs are shown separately in Studio. So never stop a Claude call because of the cap.
- Never run commands that make real API calls (spend money) unless the user asks. To check without spending: `pnpm ys plan`.
- When editing files with a script, never pass text containing `$` as the replacement string of `String.prototype.replace` (`` $` ``, `$'` and `$&` are replacement patterns; this once pasted a copy of the whole file into a note). Use the Edit tool or `split(a).join(b)`.
