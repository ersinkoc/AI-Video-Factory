## Structure
- pnpm workspace, TypeScript 7, ESM, no build step (tsx/vitest run from source). Packages export `exports: ./src/index.ts`.
- Relative imports carry the `.ts` extension (`./router.ts`).
- `packages/core`: shared Zod schemas. Money is **integer micro-dollars** everywhere (`usd()`, `formatUsd()`).
- `packages/media-gateway`: every generation call goes through here. Pipeline code never calls a provider directly.
- Providers are written as REST over `fetch` (no SDKs). Use `ctx.fetch` so tests can mock it.

- `packages/agents`: Agent SDK `query()` + `outputFormat: json_schema`. Schemas are converted to draft-07 with `toOutputSchema()` (Claude Code rejects 2020-12). Agent instructions are English; narration is in the episode language.
- `packages/pipeline`: stages are idempotent; `save()` after every sub-step. When adding a stage, think about the `STAGES` order and what `from` deletes.
- `packages/video`: Remotion; assets are read with `staticFile()` from the render folder's `public/` directory. Vector scenes (`Vector.tsx`) embed model-made SVG: every SVG is cleaned with `sanitizeSvg()`, repeating motion lives in code (no tokens spent). Render temp files go to `.render-tmp` next to the output instead of the system Temp; on a temp-file/browser error, or a page stuck on one frame (frame or delayRender timeout; 5 Nov, the Next.js episode died at 60% of an 11-min render on frame 4244, which rendered fine alone and in a shorter run), `renderEpisode` retries once from the start; a render that reports no progress for 5 min (`STALL_MS`, 3 Nov: the PC slept at 10% and Chrome never resumed, holding the lock for 7 h) is cancelled through Remotion's cancel signal and retried once the same way; "Chrome ran out of memory / could not take a screenshot" (`isMemoryFailure`, 3 Nov: the Java render died at 30% with 60 GB RAM free) is retried once with half the concurrency on the same GL backend. Only one Remotion job per machine at a time (`withRenderLock`, render + still extraction): when two episodes rendered at once, one died with a Chrome crash. Render cache (`chunks.ts`, 4 Nov: re-creating two scenes, or a render that died at 80%, rendered the whole episode again; 3-min episodes take 3–27 min, the 14-min Ottoman one hours): the picture is cut into parts at scene boundaries (`chunkRanges`; a scene longer than `CHUNK.maxSec` 60 s at a shot boundary), each keyed by everything that draws it (`chunkKeys`: frame range and size; the shots whose Sequence reaches into it, including the previous shot's transition tail (`cutsOf`); their vector drawings and side views; the contents of stills, clips and Manim boards; palette, line and texture; speech within `CHUNK.speechPadMs`; the caption pages shown, from the same `captionPages` as Episode (`cut.ts`); and `renderCode()`, a hash of the video and core sources and their package.json, so a code change renders everything again). Parts live as silent h264 MP4 in `.render-cache/<output name>` next to the output; only missing ones are rendered, consecutive ones in one Remotion call (`runsOf`; a call per part cost ~20 s each for tabs and bundle load, 9 parts took 1.8× a single render) with keyframes forced at their boundaries (`keyframesAt`, `ffmpegOverride` on the libx264 pre-stitcher) and cut without re-encoding (`split`, segment muxer; each part's frame count is checked by packet count, and on a mismatch the parts are rendered one by one). The audio is rendered separately from the light `EpisodeAudio` composition (only the audio Sequences, the same component Episode uses, so the mix is identical; 64 → 15 s) and cached by `audioKey`; `assemble` joins the parts with ffmpeg's concat demuxer without re-encoding, adds the audio and loudnorm (-14 LUFS). Files are written as `.part` first and renamed; parts no longer used are pruned after each render, so a retry after a crash resumes from the finished parts. Verified on the LLM episode (3.2 min, 9 scenes): frame count exact (5676), every part boundary ≥ 44.9 dB PSNR against a single render (51 dB average); cold render costs one render plus ~15 s of audio.
- Motion physics `packages/video/src/motion.ts`: before render, the director's animations are made physical with `physicalAnims` (things on the floor don't float or move vertically, objects don't gesture, a held object doesn't move on its own, no sitting without a seat); walk steps are counted from the distance covered (`gaitOf`, feet don't slide), slow walks are shortened to natural speed (`paceWalks`). `PlacedLayer.grounded` comes from the layout. Gestures ease in over seconds (`gestureWeight`: anticipation, overshoot, forearm lag); point reaches for its target (`target`, or the nearest thing beside); when the target is closer than the arm, the elbow bends (IK) so the fingertip stops `POINT.gap` px before its near edge (`Focus.aimEdge`, `POINT.edge` × half its box width from its centre), the hand at least `POINT.min` × the arm length from the shoulder; an edge behind the shoulder (the person stands in front of it) keeps the straight arm (3 Nov: a straight arm laid the hand over a monitor once people stood near things). Optional wrist parts `hand-l`/`hand-r` (inside the forearm, pivot in RIG; without them the pose has no effect): follow the forearm when idle, curl when waving, palm turns when explaining, a hand holding an object stays straight. Wrist roll (`handRoll`, `HAND_ROLL`; 5 Nov, user: "thumbs, elbow directions etc. need a look"): the designer draws the hand palm to the thigh with the thumb in front, which a front view shows on the inner edge (all 26 checked drawings); the hand turned with the arm, so on a sideways arm (point, shrug, give, explain, the startle's low hand, holding at chest height) the thumb pointed down, a palm turned backwards. As the downward share of that inner thumb (from the arm's total turn: shoulder + elbow + wrist + torso) rises from `from` 0.3 to `to` 0.5 the hand mirrors on the forearm's axis at the wrist (`wristsOf`: the sleeve's centre line; only hands nested in their forearm, 73 of 76), narrowing and opening the other way like a wrist turning; gesture peaks sit at ≥ 0.55 or ≤ 0.1 and a waving hand swings between −0.2 and −0.4, so it only turns while an arm rises. The CSS rule moves the origin to the axis and compensates the translate (the wrist stays put). At review frames 683 of the 1173 people with nested hands now turn a hand; elbows were checked on every gesture with three library characters and bend naturally (no change). Arm IK and measured faces (3 Nov): `ik.ts` `reach` is analytic two-bone IK (shoulder → elbow 100 px → hand contact `ARM.reach` 112; the lower-elbow solution), `rigGeometry.ts` `faceOf` measures the drawing's head/eyes/mouth groups with paper.js (group transforms included; chin = below the mouth by 0.45 × eye–mouth distance) and `fitFace` keeps a chin only inside a plausible zone (else [200, 242]); `faceFor` caches per asset (3D figures use the default). Think is the "thinker" pose (rebuilt 3 Nov, user: the chin pose looked bad in every scene; the hand sat beside the jaw near the shoulder, so the full-length upper arm threw the elbow across the chest at shoulder height and the hand hid behind the head): the hand goes under the drawing's own chin, a little toward its side (`THINK`: `jaw` × 0.4, chin + 14 px), the forearm stands 8° off vertical and the elbow sits at its end in front of the lower chest; the upper arm reaches it foreshortened toward the camera (`ik.ts` `bend`, upper-arm `sy` down to 0.62; the forearm CSS starts with the inverse scale, so only the elbow moves; 3D figures really pitch the upper arm toward the camera and the forearm undoes the pitch). The fingertips stay at least 6 px below the measured mouth (`FaceFit.lips`, `fingers` from `faceOf` `hands`, the arm's lowest point at rest, clamped 8–60 px past the contact): long-handed drawings covered the mouth and read as a gasp. The thinking arm is drawn in front of the head for the shot (`armInFront`, `Motion.front`; in the drawings the head comes after the arms). The other hand holds the elbow from below (IK); holding something in the right hand, the left hand goes to the chin without support. Think has three poses, picked per shot and layer from the seed (`thinkPoseOf`; 3 Nov: the director uses think in 6–13 shots per episode and the same pose kept repeating): chin 40%, `scratch` 30% (the hand goes to the side of the head box, `FaceFit.head`, measured if plausible else `HEAD_BOX`, at `SCRATCH.y` of its height; IK with the elbow out, `reach(..., out)`, the lower-elbow solution could cross the face; the arm stays behind the head, the hand shows at its edge; the wrist rubs at ~5 Hz in bursts), `ponder` 30% (the `CROSSED` arms of arms_crossed, head tilted toward the side the eyes look up to). Holding something: chin 55%, scratch 45%, never crossed arms. Only the chin pose moves the arm in front of the head. 3D figures push an arm toward the camera as its hand crosses toward the body centre (`ARM_FRONT`), otherwise the folded arm vanished inside the torso. Surprise reads as a startle, not joy (3 Nov: "cheerful with arms up, not worried" in 9 of 21 episodes): the `surprised` expression/gesture makes the mouth a small narrow "o" (`mouthW`, mouth sx 0.6, sy 0.3) and the gesture puts the right hand on the chest (foreshortened forearm) and raises the other hand palm out at shoulder height on the side of the person looked at (screen left when there is nobody; mirrored when that person is on the right, unless the right hand holds something, which then goes to the chest), shoulders up, leaning back away from the raised hand (`STARTLE`; 5 Nov, the reaction notes' frames opened one by one: "doesn't recoil" was noted on shots that had the gesture, and the low open hand read as presenting the table). Reactions open the mouth (`EXCLAIM`, `exclaimOf`): a person not talking whose surprised or cheer gesture is more than half in shows the talking mouth's coded shape instead of the drawing's mouth, a round "o" (E) when startled, wide open (D, with the expression's corners) when cheering, a small "o" (F) with a surprised expression and no gesture, and with a worried, sad or angry expression (negative `mood`) the coded closed mouth (X, injected only then) with its corners down by the mood (5 Nov, a close-up face sheet: the drawings' own mouths are a slight smile, so the inverted, squashed smile became a faint line or vanished; "doesn't look worried" was noted on 27% of worried and 35% of sad people although their heads were ~200 px tall in the review frame; 441 people in the review frames now frown); a talker shows the voice's shape and the reaction's in a pause. The drawing's mouth is a smile curve, so scaling it gave a flat line, never an "o". The shapes are injected for these layers too (`opensMouth`); not on 3D figures, side views or unmeasured mouths. In the review frames 206 of the 245 people with a planned reaction now open the mouth; no lint change over 1546 shots. Action gestures (3 Nov, frame inspector: "the narrated action isn't happening, the character stands stiffly"): `typing`, `writing`, `reading`, `show` (held object raised overhead; a held prop follows the posed hand), `clap`, `hands_on_hips`, `arms_crossed`, in `RIG_ONLY` and `ARM_GESTURES`; the director is told to stage the narrated action literally. Their rhythm (`gesture-timing.ts`: clap rate, key taps, pen strokes) is shared by the pose and `sfx.ts` (clap → new `clap` sound, typing → `type` with every fifth tap skipped, writing → `scratch` per stroke; first/last 8% silent). A talking (`talk`) character's mouth follows the narration's sounds (3 Nov, `visemes.ts`, `mouthShape.ts`): `visemeCues` turns word timings into Preston Blair / Rhubarb mouth shapes A–H + X from the letters (Turkish spelling is phonetic, no audio analysis; vowels last 1.6× consonants, shapes lead the sound by 40 ms, shapes under 35 ms merge into the previous one, gaps over 140 ms rest). `faceOf` also returns the mouth's parent matrix (`mouthFrame`; transform attributes on rig parts are ignored because the pose CSS overrides them) and line colour; `fitFace` accepts a mouth inside the head and smaller than 60% × 40% of it (otherwise hiding it could hide a beard). `withMouths` injects all eight spoken shapes, hidden, right after the drawing's mouth, wrapped in the inverse parent matrix so they turn with the head. They are drawn from `lipLine` (the box centre; for a big open mouth near the top), opening depth is capped at the chin, and the corners come from the expression's `mood`. Each frame, CSS hides the drawing's mouth and shows the current shape, so the SVG string is not rebuilt per frame. Silence (X), or a talk weight under 0.5, shows the drawing's own mouth. 3D figures and unmeasurable mouths scale the mouth part with `VISEME_SCALE`. Speech beats (`beats.ts`, 3 Nov: the body used to move on fixed sine rhythms and random timers, out of step with the voice). A beat is a phrase start (the first word after a pause of 250 ms or more, strength 1) or a word of four or more syllables (0.6); beats are at least 700 ms apart. While a character talks, the head dips on each beat (`nod`) and the brows lift at phrase starts. The spontaneous hand stroke peaks on a phrase start (`armBeats`, at least 2.2 s apart; `strokeAt`: prep 350, hold 500, retract 450 ms) instead of the random timer, and the explaining hand beats down on stressed words. `Timeline.speech` is filled even with captions off; old timelines use a fixed rhythm. Word timings without provider timestamps (Gemini TTS) are aligned to the recorded voice in the voice stage (`pipeline/src/align.ts`, 3 Nov). Before this, the duration was split by letter count, pauses were spread over every word and a scene had no gaps at all: the lips talked through pauses, and captions and beats drifted (2 phrase starts per minute). `detectSilences` (media.ts, ffmpeg silencedetect at −35 dB, at least 0.12 s) finds the pauses. Silences less than 100 ms apart merge, and silences within 150 ms of either end are the lead and tail. A DP matches the inner silences, in order, to the text's punctuation pauses. Its cost is segment share × 10 × ln(rate / mean rate)², plus skip penalties: sentence end 1.5, comma 0.3, silence of 250 ms or more 1, shorter 0.2. Within each phrase, time is split by letters (digits count ×3). Without silences (no ffmpeg or filter) the punctuation pauses are estimated: sentence 380 ms, comma 180 ms, at most 30% of the clip. Measured on real narration: 16–17 phrase starts and 23 mouth rests per minute. Only new voice runs are aligned; existing episodes keep their timings, because shots are planned on them. Standing pose (3 Nov, frame inspector: "stands stiffly" in all eight reviewed episodes): a standing, front-view character puts the weight on one leg. The bearing leg turns in, the relaxed leg turns out with the knee bent, the upper body leans over the bearing leg, the head counter-tilts and the relaxed elbow bends (`STANCE`, `stanceAt`); the weight moves to the other leg every 9–14 s over 0.9 s, seeded per character, and fades out with walking. A listener (no arm gesture, no talk, no walk, holding nothing, not sitting, not in side view) also gets a rest pose for the shot (`restPoseOf`: relaxed 45%, one hand on the hip 25%, hands together in front of the belly by IK 30%) and makes no spontaneous gestures. The expression picks the rest pose when it has a body (`MOOD_REST`, `MOOD_POSE`; 5 Nov: a worried, sad or angry listener stood in a random rest pose, often relaxed with spontaneous explaining hands, so in a wide shot nothing but a small face carried the emotion): worried hands clasped in front, wringing (wrists turning opposite ways), shoulders raised; angry arms crossed (`CROSSED`); sad slumped (torso shortened from the hip, head lowered, arms hanging, no spontaneous gestures). 52 people over the existing timelines (the other 474 with these expressions talk, gesture, walk, sit or hold something); no lint change. Facing (4 Nov, review: "they face the viewer instead of each other" in 76 of 2014 reviewed shots): a person with someone else in the shot turns to the nearest person (`facingOf`: a listener fully, a talker `FACING.talker`, as a narrator also talks to the viewer; faded continuously by point, give, typing, writing, reading, think, show and by walking, so nothing snaps). A front drawing slides its eyes, brows and mouth inside the head toward them and tilts the head (`FACING` px/degrees, a three-quarter head); the nose, which no drawing labels (`rigGeometry` `noseOf`: small shapes in the head outside the eyes, brows and mouth groups, between the eyes and ending above the mouth, consecutive siblings; found in 124 of 133 drawings, 12 checked by eye), is grouped at render (`faceSvgFor`, `<g id="nose">`) and slides by the part of the eyes' shift (facing, glances, `shake_head`, the thinking look) that exceeds the gap beside it (`noseShift`, `Nose.room`, 1 px short of touching; 6 Nov, user: "the nose can still sit in odd places, the eyes too"; on the Antik Mısır face sheet a narrow-faced worker's eye and kohl line ran over the face outline when he turned to someone: 29 of 149 drawings have under 6 px of room, 23 none), and what the eyes cannot slide the pupils do inside the whites (`pupilsOf`: dark shapes inside a light shape of the eyes group plus their light highlights, consecutive siblings, grouped as `<g id="pupils">`; a 3D figure really turns `FACING.yaw` × 90° on top of the walking turn and does not slide its features. `nod` is a vertical nod (the head dips, eyes and brows dip a little more inside it); `shake_head` turns the head side to side (features slide inside the head, brows knit); `give` reaches toward the receiver (`target`, else the nearest person) at waist-to-chest height by IK, using the holding right hand even across the body, so the held prop follows. Personal space (`SPACE`, 4 Nov, Uçak s8-sh6: Wilbur pointed at Charlie while Charlie explained toward him, and their hands met mid-air; 22 of 328 two-person shots): `focusOf` returns the midline to the nearest person at the same depth (`Focus.space`, z within `CONVERSE.depth`; `Attention.space`, not while giving); a pointing fingertip stops before it (with a person as the stop the shortest reach is `SPACE.min` instead of `POINT.min`), and explain, shrug and the startle's low hand scale their outward arm angles until the fingertips stay `SPACE.gap` short of it (`keepInSpace`, a continuous scale; a per-frame IK clamp snapped joints in 49 shots because a nearly straight arm bends tens of degrees for a few pixels); overlapping people are left alone. 22 → 14 two-person shots with hands meeting; no new lint findings over 1319 shots. Torso, arms and head are wrapped into one group at render (`wrapTorso`; sibling groups in the drawing). The neck the designer draws inside the head group (so it turns with the head) is moved in front of the body group at render (`rigGeometry` `neckOf`: shapes directly in the head, drawn before the face (the largest head shape around the mouth), centred, narrow and reaching below the chin; `neckBehind`, only when body and head are siblings and the body comes first), gets the head's transform as its own rule (same pivot) and is wrapped with the torso; the collar now covers its base and a V-neck still shows it (5 Nov, user: "the neck sits on top of the clothes": in 115 of the 121 drawings with a neck it ran 8–38 px down over the collar, 119 found and checked by eye) and bend together from the hip (`torso` pose: weight shift when idle, toward the direction of travel when walking, toward the listener when explaining, toward the target when pointing, back when surprised; a held object follows). A character with an object in the right hand holds it to the side at chest height (`HOLD_POSE`) and makes spontaneous gestures with the left hand. On-screen text (`layoutTexts`): styles other than label go in a fixed info card at the top-left (the director's x/y is ignored); a label has one size and sits above a person's head: the character whose name appears in the label (`namesMatch`, the name in the quality-gate record), otherwise the head nearest the director's point; it moves with the camera and with walking (`cameraPoint`); the label of a character not in the shot or whose face is out of frame (`faceOnScreen`) is hidden (filtered before the two-text limit, takes no slot; the director is told the card and labels count together). First-appearance name tag (`pipeline/src/name-tags.ts` `nameTags`, in `varyShots` after every plan and replan; 4 Nov: in 21 episodes only 17 of 68 people were named where they first appear, Ballmer in scene 8, Shannon in his 13th of 31 shots, Schmidt, Karpathy and Zuckerberg never; the review said "unclear who is who", "no name label"; scenes are planned in parallel, so no director call knows where a person first appears): a cast person gets a label in the first of their first `NAME_TAG.within` 3 shots with room under the two-text limit, unless one of those shots already names them. A label only drops below a card/label it overlaps horizontally (two people side by side keep their labels on their own heads). Captions: render always writes `<id>.srt`; if `input.captions === false` they are not burned in (`onScreen`; draft/review stills are also caption-free, the inspector is told there are no captions and the `text_on_subtitles` defect is dropped; Studio `set-captions` reopens only the render). A wall/air item more than half covered by furniture is moved in front of that furniture (`resolveLayout`). A prop on a surface stays on it whole (`ON_SURFACE`, `surfaceRoom`: its centre within `center` 0.8 of the surface's half width and both its edges within `edge` 0.9; one wider than the surface is centred; 8 Nov, IPv4 s1-sh3: only the centre was limited, so a wide Commons laptop put near the desk end hung half off it, "the laptop hangs in mid-air beside the desk"; 90 of the 595 props on surfaces over all timelines stuck out of their surface, now 20); sliding along the surface to clear a face behind tries the whole-on-surface range first, then the old centre-only range, else keeps the director's spot clamped the old way (a seated person behind a monitor); no lint change. A giant floor object is in the distance (`GIANT`, `PlacedLayer.distant`; 6 Nov, the first draft review on the newest code, Elon Musk: the 22.5 m Falcon 1 at real size beside Musk showed only its stand and pad, "no rocket" in 10 of 40 shots; over all timelines 256 placements of 63 objects, warships, galleys, city walls, Rumeli Hisarı, Hagia Sophia, towers, showed a strip of their base): a grounded prop taller than `GIANT.over` × the room between its foot line and the frame top (less than half of it would show) shrinks to `GIANT.fit` of that room, as a real camera sees such a thing whole only from afar; a slight overflow (a 4 m tent, a door) keeps its real size. `fillWide` keeps a distant object whole, base included (it may otherwise lose the bottom quarter like a tall machine, and the camera moving in cut the rocket's nose). 167 placements of 38 objects now show whole; the 89 left are slight overflows. In a static wide shot, if the content fills only a small part of the frame, `fillWide` moves in to a medium shot (at most 1.8; a person may be cut at the knees, furniture with something on it or someone sitting on it at half height, a floor object at least `FILL.tall` of the tallest person's height (a machine, a cabinet, a horse) may lose up to its bottom `FILL.base` quarter like a person's legs (4 Nov audit: keeping every floor object whole capped the zoom in 273 of 968 wide shots; 57 more static wide shots now fill), other objects and every object in a shot without people stay whole and above the caption band; not when something walks or slides); if moving in isn't worth it but the content is piled to one side (more than 15% of the frame width from the director's view centre), it is recentred at the director's zoom, but not with a panning camera (panX). - Atmosphere (`Ambience.tsx`): particle kinds (rain + splashes, snow, dust, embers, confetti) use PixiJS/WebGL (`PixiParticles`, `particles.ts`): the Pixi ticker is off, every frame is computed statelessly from `particleFrame(kind, seed, t)` and rendered by hand (parallel tabs get the same frame); `delayRender` until Pixi is ready; if WebGL can't start the layer stays empty and the render doesn't fail. Fog, flicker and light rays are CSS gradients. Thinking (`quizzical`, `QUIZZICAL`): one brow (seeded) rises with its outer end arched, the other drops slightly; the think gesture adds it unless the expression already does; shake_head knits the brows. The render writes brow rules only when the split worked (side views, 3D figures and unsplittable drawings keep the whole-group motion). 3D figures have `brow-l`/`brow-r` groups at ±27 px so the same pose tilts them. Known limit: a drawing whose brows touch same-coloured hair loses them in the hair when raised (surprised).
- Pronunciation (`pipeline/src/pronounce.ts`, `agents/src/pronounce.ts`; 3 Nov, user: Gemini TTS read "C++" in Turkish narration as "si artı artı"). A TTS voice reads every word by the narration language's spelling, so foreign names, brands, abbreviations and symbols came out wrong. The voice stage sends the TTS a respelled text (`sayPlan`): the built-in `LEXICON[lang]` (common tech terms; case-insensitive whole words, a suffix after an apostrophe is kept: "C++'ın" → "si pılas pılas'ın"; multi-word names match as a whole, longest first) plus `state.pronunciations` (the cheap `pronouncer` agent's finds, one call per voice run; it never overrides the lexicon or a hand edit, and a failure logs and continues with the lexicon). Word timings (provider timestamps, or `alignWords` on the spoken text) map back to the written words by letter position (`restoreWords`): captions keep the written form, a respelled word carries `WordTiming.say`, which visemes and speech beats use; `SceneVoice.spoken` keeps the text sent to the TTS. Existing voices are not redone automatically. Numbers (`pipeline/src/numbers.ts`, 4 Nov, user: "the Turkish wording of numbers can be comic"): the screenwriter and script doctor used to be told to spell numbers out and wrote "Intel 4004" as "Dört bin dört" in the captions; now `NUMBERS_AND_NAMES` tells them to write digits in the language's conventions and keep names in their original spelling, and `sayPlan(text, terms, "tr")` reads what the lexicon did not match: ordinals ("II. Mehmed", "19. yüzyıl", numbers up to 20 before a capital: "1. Dünya Savaşı"), decimal comma ("1,5" → "bir buçuk"), thousands dot, versions after a name ("Python 3.12" → "nokta"; a following "milyon" makes it a decimal), %, currencies (moved after "milyar", suffix re-harmonized: `harmonize`), "10x" → "kat", ranges → "ile", fractions ("dörtte üç"), times, "64-bit", "GPT-2", MÖ/MS, ≈/~, abbreviations (`sayAbbreviation`: the dot is dropped before a lowercase word or after a title). The writer's suffix after the apostrophe is kept ("1453'te"). A number inside a name said differently (a chip) comes from the pronouncer, which is told not to list plain numbers. Abbreviations read out in full (4 Nov, user: "TBMM should be Türkiye Büyük Millet Meclisi"): the lexicon has TBMM, ABD, AB, BM, SSCB, TDK, MEB, THY, TCDD; the pronouncer expands context-specific ones (CHP…), gives acronyms said as words as a lowercase word so the voice cannot spell them (user: "if COBOL is written, don't invent anything, say kobol"; COBOL, FORTRAN, NASA, NATO, UNESCO, TÜBİTAK, RAM, BIOS… are in the lexicon that way), spells the rest (PTT) and leaves out what it is not sure of; the screenwriter keeps abbreviations as written. The writer's suffix matches the letter reading ("ABD'ye"), so for an all-caps term expanded to several words `attachSuffix` rebuilds it: pronominal n after a compound ending in a possessive ("Devletleri'ne", "Birliği'nden", instrumental "Meclisi'yle"), no buffer after a consonant ("Milletler'e", "Milletler'in"), vowel harmony.

## Rules
- **Cost first:** a new provider must have `price` and `qualityPrior`. Cite the price source in a comment. If there is a local (ComfyUI) option, prefer it.
- If you are not sure about an endpoint or field names, add the spec with `verified: false`.
- Code comments are Turkish; the Studio UI is Turkish + English (from the dictionary). Pipeline log lines and user-facing errors are written with `msg("log.…"/"err.…")` + `LocalizedError`, their texts live in the `core/src/messages/` catalogue (TR + EN required); Studio shows the selected language, the CLI prints Turkish. The Turkish template must stay identical to the old output (the `WARN` level looks at the Turkish text).
- After every change: `pnpm typecheck && pnpm test`. Test coverage is 100% (lines, branches, functions, statements; threshold in `vitest.config.ts`): new code comes with tests, and `pnpm test:coverage` fails if it drops. No real network/Claude/Chrome/ffmpeg in tests (fake `fetch`, `queryFn`, `vi.mock`). Studio client components are tested in `apps/studio/test/client` (happy-dom), the server side in `apps/studio/test/server`. `/* v8 ignore */` only for truly unreachable defensive code, with a reason; oxc drops comments inside a variable initializer, a parenthesized expression or an array element, so the hint has no effect there: put it on the line before the statement.
- The budget cap is only for paid image/audio/video APIs (`ledger.spent` doesn't count "llm" entries). Claude agent calls may exceed the cap (user decision, 30 Oct); their costs are shown separately in Studio. So never stop a Claude call because of the cap.
- Never run commands that make real API calls (spend money) unless the user asks. To check without spending: `pnpm ys plan`.
- When editing files with a script, never pass text containing `$` as the replacement string of `String.prototype.replace` (`` $` ``, `$'` and `$&` are replacement patterns; this once pasted a copy of the whole file into a note). Use the Edit tool or `split(a).join(b)`.
