# AI Video Factory: project notes for Claude

Plan and architecture: `docs/PROJE_PLANI.md` (Turkish). Before changing a major decision, read the relevant section there and update it if needed.
The README is English (`README.md`) with a Turkish copy (`README-TR.md`): when you change one, update the other. CHANGELOG and release notes are English. This file is English.

## Structure
- pnpm workspace, TypeScript 7, ESM, no build step (tsx/vitest run from source). Packages export `exports: ./src/index.ts`.
- Relative imports carry the `.ts` extension (`./router.ts`).
- `packages/core`: shared Zod schemas. Money is **integer micro-dollars** everywhere (`usd()`, `formatUsd()`).
- `packages/media-gateway`: every generation call goes through here. Pipeline code never calls a provider directly.
- Providers are written as REST over `fetch` (no SDKs). Use `ctx.fetch` so tests can mock it.

- `packages/agents`: Agent SDK `query()` + `outputFormat: json_schema`. Schemas are converted to draft-07 with `toOutputSchema()` (Claude Code rejects 2020-12). Agent instructions are English; narration is in the episode language.
- `packages/pipeline`: stages are idempotent; `save()` after every sub-step. When adding a stage, think about the `STAGES` order and what `from` deletes.
- `packages/video`: Remotion; assets are read with `staticFile()` from the render folder's `public/` directory. Vector scenes (`Vector.tsx`) embed model-made SVG: every SVG is cleaned with `sanitizeSvg()`, repeating motion lives in code (no tokens spent). Render temp files go to `.render-tmp` next to the output instead of the system Temp; on a temp-file/browser error `renderEpisode` retries once from the start; a render that reports no progress for 5 min (`STALL_MS`, 3 Nov: the PC slept at 10% and Chrome never resumed, holding the lock for 7 h) is cancelled through Remotion's cancel signal and retried once the same way; "Chrome ran out of memory / could not take a screenshot" (`isMemoryFailure`, 3 Nov: the Java render died at 30% with 60 GB RAM free) is retried once with half the concurrency on the same GL backend. Only one Remotion job per machine at a time (`withRenderLock`, render + still extraction): when two episodes rendered at once, one died with a Chrome crash.
- Motion physics `packages/video/src/motion.ts`: before render, the director's animations are made physical with `physicalAnims` (things on the floor don't float or move vertically, objects don't gesture, a held object doesn't move on its own, no sitting without a seat); walk steps are counted from the distance covered (`gaitOf`, feet don't slide), slow walks are shortened to natural speed (`paceWalks`). `PlacedLayer.grounded` comes from the layout. Gestures ease in over seconds (`gestureWeight`: anticipation, overshoot, forearm lag); point reaches for its target (`target`, or the nearest thing beside); when the target is closer than the arm, the elbow bends (IK) so the fingertip stops `POINT.gap` px before its near edge (`Focus.aimEdge`, `POINT.edge` × half its box width from its centre), the hand at least `POINT.min` × the arm length from the shoulder; an edge behind the shoulder (the person stands in front of it) keeps the straight arm (3 Nov: a straight arm laid the hand over a monitor once people stood near things). Optional wrist parts `hand-l`/`hand-r` (inside the forearm, pivot in RIG; without them the pose has no effect): follow the forearm when idle, curl when waving, palm turns when explaining, a hand holding an object stays straight. Arm IK and measured faces (3 Nov): `ik.ts` `reach` is analytic two-bone IK (shoulder → elbow 100 px → hand contact `ARM.reach` 112; the lower-elbow solution), `rigGeometry.ts` `faceOf` measures the drawing's head/eyes/mouth groups with paper.js (group transforms included; chin = below the mouth by 0.45 × eye–mouth distance) and `fitFace` keeps a chin only inside a plausible zone (else [200, 242]); `faceFor` caches per asset (3D figures use the default). Think is the "thinker" pose (rebuilt 3 Nov, user: the chin pose looked bad in every scene; the hand sat beside the jaw near the shoulder, so the full-length upper arm threw the elbow across the chest at shoulder height and the hand hid behind the head): the hand goes under the drawing's own chin, a little toward its side (`THINK`: `jaw` × 0.4, chin + 14 px), the forearm stands 8° off vertical and the elbow sits at its end in front of the lower chest; the upper arm reaches it foreshortened toward the camera (`ik.ts` `bend`, upper-arm `sy` down to 0.62; the forearm CSS starts with the inverse scale, so only the elbow moves; 3D figures really pitch the upper arm toward the camera and the forearm undoes the pitch). The fingertips stay at least 6 px below the measured mouth (`FaceFit.lips`, `fingers` from `faceOf` `hands`, the arm's lowest point at rest, clamped 8–60 px past the contact): long-handed drawings covered the mouth and read as a gasp. The thinking arm is drawn in front of the head for the shot (`armInFront`, `Motion.front`; in the drawings the head comes after the arms). The other hand holds the elbow from below (IK); holding something in the right hand, the left hand goes to the chin without support. Think has three poses, picked per shot and layer from the seed (`thinkPoseOf`; 3 Nov: the director uses think in 6–13 shots per episode and the same pose kept repeating): chin 40%, `scratch` 30% (the hand goes to the side of the head box, `FaceFit.head`, measured if plausible else `HEAD_BOX`, at `SCRATCH.y` of its height; IK with the elbow out, `reach(..., out)`, the lower-elbow solution could cross the face; the arm stays behind the head, the hand shows at its edge; the wrist rubs at ~5 Hz in bursts), `ponder` 30% (the `CROSSED` arms of arms_crossed, head tilted toward the side the eyes look up to). Holding something: chin 55%, scratch 45%, never crossed arms. Only the chin pose moves the arm in front of the head. 3D figures push an arm toward the camera as its hand crosses toward the body centre (`ARM_FRONT`), otherwise the folded arm vanished inside the torso. Surprise reads as a startle, not joy (3 Nov: "cheerful with arms up, not worried" in 9 of 21 episodes): the `surprised` expression/gesture makes the mouth a small narrow "o" (`mouthW`, mouth sx 0.6, sy 0.3) and the gesture puts the right hand on the chest (foreshortened forearm) with the left hand open low at the side, leaning back. Action gestures (3 Nov, frame inspector: "the narrated action isn't happening, the character stands stiffly"): `typing`, `writing`, `reading`, `show` (held object raised overhead; a held prop follows the posed hand), `clap`, `hands_on_hips`, `arms_crossed`, in `RIG_ONLY` and `ARM_GESTURES`; the director is told to stage the narrated action literally. Their rhythm (`gesture-timing.ts`: clap rate, key taps, pen strokes) is shared by the pose and `sfx.ts` (clap → new `clap` sound, typing → `type` with every fifth tap skipped, writing → `scratch` per stroke; first/last 8% silent). A talking (`talk`) character's mouth follows the narration's sounds (3 Nov, `visemes.ts`, `mouthShape.ts`): `visemeCues` turns word timings into Preston Blair / Rhubarb mouth shapes A–H + X from the letters (Turkish spelling is phonetic, no audio analysis; vowels last 1.6× consonants, shapes lead the sound by 40 ms, shapes under 35 ms merge into the previous one, gaps over 140 ms rest). `faceOf` also returns the mouth's parent matrix (`mouthFrame`; transform attributes on rig parts are ignored because the pose CSS overrides them) and line colour; `fitFace` accepts a mouth inside the head and smaller than 60% × 40% of it (otherwise hiding it could hide a beard). `withMouths` injects all eight spoken shapes, hidden, right after the drawing's mouth, wrapped in the inverse parent matrix so they turn with the head. They are drawn from `lipLine` (the box centre; for a big open mouth near the top), opening depth is capped at the chin, and the corners come from the expression's `mood`. Each frame, CSS hides the drawing's mouth and shows the current shape, so the SVG string is not rebuilt per frame. Silence (X), or a talk weight under 0.5, shows the drawing's own mouth. 3D figures and unmeasurable mouths scale the mouth part with `VISEME_SCALE`. Speech beats (`beats.ts`, 3 Nov: the body used to move on fixed sine rhythms and random timers, out of step with the voice). A beat is a phrase start (the first word after a pause of 250 ms or more, strength 1) or a word of four or more syllables (0.6); beats are at least 700 ms apart. While a character talks, the head dips on each beat (`nod`) and the brows lift at phrase starts. The spontaneous hand stroke peaks on a phrase start (`armBeats`, at least 2.2 s apart; `strokeAt`: prep 350, hold 500, retract 450 ms) instead of the random timer, and the explaining hand beats down on stressed words. `Timeline.speech` is filled even with captions off; old timelines use a fixed rhythm. Word timings without provider timestamps (Gemini TTS) are aligned to the recorded voice in the voice stage (`pipeline/src/align.ts`, 3 Nov). Before this, the duration was split by letter count, pauses were spread over every word and a scene had no gaps at all: the lips talked through pauses, and captions and beats drifted (2 phrase starts per minute). `detectSilences` (media.ts, ffmpeg silencedetect at −35 dB, at least 0.12 s) finds the pauses. Silences less than 100 ms apart merge, and silences within 150 ms of either end are the lead and tail. A DP matches the inner silences, in order, to the text's punctuation pauses. Its cost is segment share × 10 × ln(rate / mean rate)², plus skip penalties: sentence end 1.5, comma 0.3, silence of 250 ms or more 1, shorter 0.2. Within each phrase, time is split by letters (digits count ×3). Without silences (no ffmpeg or filter) the punctuation pauses are estimated: sentence 380 ms, comma 180 ms, at most 30% of the clip. Measured on real narration: 16–17 phrase starts and 23 mouth rests per minute. Only new voice runs are aligned; existing episodes keep their timings, because shots are planned on them. Standing pose (3 Nov, frame inspector: "stands stiffly" in all eight reviewed episodes): a standing, front-view character puts the weight on one leg. The bearing leg turns in, the relaxed leg turns out with the knee bent, the upper body leans over the bearing leg, the head counter-tilts and the relaxed elbow bends (`STANCE`, `stanceAt`); the weight moves to the other leg every 9–14 s over 0.9 s, seeded per character, and fades out with walking. A listener (no arm gesture, no talk, no walk, holding nothing, not sitting, not in side view) also gets a rest pose for the shot (`restPoseOf`: relaxed 45%, one hand on the hip 25%, hands together in front of the belly by IK 30%) and makes no spontaneous gestures. `nod` is a vertical nod (the head dips, eyes and brows dip a little more inside it); `shake_head` turns the head side to side (features slide inside the head, brows knit); `give` reaches toward the receiver (`target`, else the nearest person) at waist-to-chest height by IK, using the holding right hand even across the body, so the held prop follows. Torso, arms and head are wrapped into one group at render (`wrapTorso`; sibling groups in the drawing) and bend together from the hip (`torso` pose: weight shift when idle, toward the direction of travel when walking, toward the listener when explaining, toward the target when pointing, back when surprised; a held object follows). A character with an object in the right hand holds it to the side at chest height (`HOLD_POSE`) and makes spontaneous gestures with the left hand. On-screen text (`layoutTexts`): styles other than label go in a fixed info card at the top-left (the director's x/y is ignored); a label has one size and sits above a person's head: the character whose name appears in the label (`namesMatch`, the name in the quality-gate record), otherwise the head nearest the director's point; it moves with the camera and with walking (`cameraPoint`); the label of a character not in the shot or whose face is out of frame (`faceOnScreen`) is hidden (filtered before the two-text limit, takes no slot; the director is told the card and labels count together). A label only drops below a card/label it overlaps horizontally (two people side by side keep their labels on their own heads). Captions: render always writes `<id>.srt`; if `input.captions === false` they are not burned in (`onScreen`; draft/review stills are also caption-free, the inspector is told there are no captions and the `text_on_subtitles` defect is dropped; Studio `set-captions` reopens only the render). In a close-up, if the subject is smaller than 20% of the frame, `closeUpCamera` zooms in and centres; a surface with things on it (a desk) is never the subject, objects on the same surface are framed together (`PlacedLayer.on`); other objects visible in the director's framing stay in frame, and even when the subject is big enough, focus shifts / zoom drops for an object that doesn't fit (a screen cut off at the bottom, an overflowing magazine) (`fitWhole`; a character may be cut on purpose). In a close-up a held object or one placed on a desk becomes the subject before the person (size is the square root of area, target 40% of the frame; the holder's head stays in frame, the face is never cut; so does the head of a person standing beside / at the desk of the object); the camera takes the held object's position from the hand in the holding pose (`heldFraming`). A wall/air item more than half covered by furniture is moved in front of that furniture (`resolveLayout`). In a static wide shot, if the content fills only a small part of the frame, `fillWide` moves in to a medium shot (at most 1.8; a person may be cut at the knees, furniture with something on it or someone sitting on it at half height, other objects stay whole and above the caption band; not when something walks or slides); if moving in isn't worth it but the content is piled to one side (more than 15% of the frame width from the director's view centre), it is recentred at the director's zoom, but not with a panning camera (panX). In a wide shot (zoom 1–1.5) `frameWide` keeps characters with their heads and small objects in frame (except those entering): panning is dropped, focus shifts, zoom drops if needed. A character appears at most once per shot (`uniqueCharacters`: duplicates are dropped in the plan and at render); when a layer is dropped, index references (`on`, `heldBy`, point `target`) are remapped with `keepLayers`. Side view (`input.sideViews`, off by default): characters that move get a second drawing facing right per `RIG_SIDE` (`vectorSideViews`; the gate compares it with the front drawing, key `<front>.side.svg`), `<id>~side` in the timeline; render turns to it while walking.
- Atmosphere (`Ambience.tsx`): particle kinds (rain + splashes, snow, dust, embers, confetti) use PixiJS/WebGL (`PixiParticles`, `particles.ts`): the Pixi ticker is off, every frame is computed statelessly from `particleFrame(kind, seed, t)` and rendered by hand (parallel tabs get the same frame); `delayRender` until Pixi is ready; if WebGL can't start the layer stays empty and the render doesn't fail. Fog, flicker and light rays are CSS gradients. `pixi.js` is faked in tests.
- Globe maps (`projection: "globe"`) are 3D with three.js (`Globe3D.tsx`, maths in `globe.ts`): `generateMap` returns `meta.globe` next to the SVG (centre/radius of the orthographic projection + an equirectangular 4096×2048 texture SVG, sanitized). The orthographic camera gives the same image as d3's projection: the globe rotates in during the first 25% of the shot (`globeView`), and once it stops the SVG's routes/markers and labels sit exactly on it (the SVG base group `globe-base` is hidden; `MapOverlay` plays with `overlayProgress`). three has no loop, every frame is rendered by hand; `delayRender` until the texture loads, empty layer without WebGL. Old globes without `meta.globe` stay SVG. `three` is faked in tests (`globe3d.test.tsx`); rotation maths is tested with real three (`globe-math.test.ts`).
- 3D figures (`core/figure.ts` `FigureSpec`, `video/src/figure3d.ts`, `Figure3D.tsx`; user request 3 Nov: non-realistic but distinctive 3D characters): a character asset with `meta.figure` is drawn as a soft-lit three.js puppet built in code from parameters (skin, hair style, beard, glasses, top/bottom, shoes, build, finish matte/clay/glossy/faceted) instead of its SVG. Joints sit on the `RIG` pivots and the same `rigPose` output is applied (`poseFigure`: rotate = −z, ty down, scale at the pivot), so physics, gestures, blinking and the talking mouth are unchanged; the orthographic camera matches the rig canvas, so held objects, labels and framing still line up. Walking: the figure really turns (`Motion.turn`, partial yaw below half gait, full profile above it) and takes the side pose (`profile`: rotate → local x axis, tx → forward), no side SVG and no squash needed; `handPoint` uses `RIG_SIDE` whenever `profile`. The SVG is kept (gate, fallback when WebGL fails). Contact shadow is a CSS gradient. Pipeline: packs with `StylePack.figure` (soft-3d matte, clay, vinyl-toy glossy, low-poly faceted) get figures; at the end of the concept stage `figures()` shows each selected character's approved SVG (plus up to two saved reference photos) to the cheap `figure-designer` agent and writes `figure` (with the pack's finish) into the library meta once; keyframes/timeline (`vectorAssets(state, stage)`) fill in missing ones (a selection changed in Studio). A failure logs and keeps the SVG. Backgrounds and props stay SVG. Previews: `renderFigurePreviews` renders the "Figure" composition (`FigurePreview.tsx`, 520×864 transparent PNG, slight turn) for all missing figures in one Remotion job under `ifRenderFree` (if another render holds the machine lock it returns undefined instead of waiting; the next stage retries). The PNG sits next to the SVG (`<key>.figure.png`, `meta.figurePreview`, cleared when the figure is redone); `state.figurePreviews` (SVG key → PNG) feeds the Studio concept card (3D badge), `LibraryCharacter.figurePreview` the character bank, the style-samples index `figure` the gallery (`drawStyleSamples` prepares figures for 3D-pack samples).
- Render GL backend (`renderGl`, `YS_RENDER_GL`, default `angle` = GPU): measured 3 Nov on 90 frames, vector shot 12.2 → 7.5 s, 3D-figure shot 56 → 8.2 s vs software GL. A render that fails with a GPU/browser crash (`isGpuFailure`) is retried once with `swangle`. Stills and thumbnails use the same backend.
- Callout (`video/src/callout.ts`, 3 Nov: the frame inspector flagged "key prop small/unreadable" in ~60% of frames): `VectorShot.callout` (director, a small prop's layer index) or, without it, a small held prop gets a round magnified inset with a dashed pointer to the prop (`calloutTarget`: not in close-ups ≥1.5, maps, Manim shots or thumbnails `insets={false}`; asked props up to 25% of the frame height, auto ones under 10%; without a held one, the smallest prop resting on a surface under 6% gets it — the director almost never sets `callout`, 0 of 27 shots in the Java plan). `calloutSpot` picks the upper/middle candidate that covers the least face, text or the prop itself. `keepShotLayers` remaps `callout` when layers are dropped. Ambience is drawn inside `VectorScene` (sized to the 1920×1080 stage): confetti/embers/dust behind the character layers, rain/snow/fog/flicker/rays over the stage; all under the callout, texts and the Manim board. Name tags anchor at the drawn head top (`HEAD_TOP`, 10% below the box top), not the box top. The info card flips to the top right (right-aligned, bar on the right) when on-screen heads/upper bodies cover more than 15% of it on the left and the right is clearly freer. Layout: two standing people at the same depth (z within 25) further apart than `CONVERSE.max` (1.5 m between centres) close the excess half each (3 Nov: "stand far apart, not interacting" dozens of times per episode; 37% of side-by-side pairs were over 2 m apart); something between them at body height (desk, board, wall screen) is not crossed, they stop at its edges; a person pointing at a non-person on their outer side stays and the other closes the gap; repeated until no pair moves (three in a row); only wide shots (director zoom under 1.5) without a Manim board, not entering/walking or sitting people (`converse`, before the face-cover passes). A standing character in front that covers a face behind moves to the nearest x that covers none; several people sitting on one seat are spread along it in the director's x order; an object on a surface that covers the face of a person behind it slides along the surface (no room: a standing, non-entering person steps aside). Framing (`jointSafe`, last camera pass for wide/medium shots incl. `fillWide`): a standing person is never cut between the feet and mid-thigh (feet in frame with 1% margin, or cut ≥ 27% of their height from the bottom); the smallest vertical focus shift that satisfies this at both ends of the shot is taken, keeping heads and props that were whole; otherwise the camera is unchanged. Person close-up (`portrait` in `closeUpCamera`, 3 Nov): when the close-up subject is a still character seen in the director's frame and no held/surface prop is the subject, the seen characters are framed from the waist up (head top at 7% headroom, cut at 44% of the height from the bottom, shoulders within 80% of the width, other whole items seen stay in frame; zoom capped at 3.2, only if it gains ≥10% over the director's). 3D figures get a canvas at screen resolution (`Figure3D` `scale` = layer height × max zoom / 800, between `FIGURE_VIEW.px` and `maxPx`, rounded to 0.1 so the renderer is not rebuilt). Shot-size variety (`pipeline/src/variety.ts`, after the shot plan and after draft replans): scenes are planned in parallel, so two consecutive shots across a scene boundary often showed the same room, people and size; the second one steps wide → medium (1.3–1.4 on the people), medium → close (1.7–1.85 on the lead), close → medium. Panning cameras, Manim shots and shots without people are left alone.
- `draw_on` layer animation (`drawOn.ts`): the object appears as if drawn by hand. `drawPlan` marks drawable elements (except those inside `defs`/`clipPath`/`mask`…) with `data-draw` and measures their lengths from path data with paper.js (`paper/dist/paper-core`; `importSVG` is not used, it needs an iframe); strokes are drawn in document order in time proportional to length (80% of the progress), fills follow, elements without a stroke get a temporary ink line. `drawCss` only produces CSS each frame and writes no rule for finished elements (original look; `pathLength` is not used so dashed lines in the design survive). Broken path data has length 0: the element appears whole when its turn comes.
- Text reveal pace (`revealWindow` in `kinetic-timing.ts`, 3 Nov: the director often gives a text animation the whole shot, so a six-word title opened over 6–8 s and most frames showed half a text): `kinetic` plays at 1.25× its GSAP length, `typewriter` at 16 characters/s, `count_up` in at most 2.2 s, then the text holds; a shorter window is kept. Render and `sfx.ts` use the same window.
- `kinetic` text animation (`kinetic.tsx`, GSAP): the plate wipes open from the left, words rise one by one in masked boxes. The GSAP timeline is paused and its own clock is not used; `progress(q)` every frame (parallel tabs get the same frame). When the animation ends, `revert()` removes the inline styles. HyperFrames was not adopted because it is a separate render engine (user decision, 2 Nov): its animation engine, GSAP, runs directly inside Remotion. Real GSAP in tests (happy-dom).
- Manim board (`pipeline/src/manim.ts`): the director gives a shot a `math` recipe (LaTeX steps + a line/bar graph with data points); in the timeline stage (`mathBoards`, vector only) code writes the Manim script from the recipe and local Manim renders a transparent WebM (`MATH_BOARD` 1040×560, key `library/math/<recipe+duration+colour hash>.webm`, `MATH_VERSION`). The model's code never runs; LaTeX passes the `safeLatex` allow-list (ASCII, allowed commands, no `^^`/`%`/`#`/`$`), texts are embedded as JSON strings. If Manim is missing or fails, the shot goes on without a board. `overlay` in the timeline; Episode plays it in the `MathBoard` panel (fixed to the screen, centred). Render and draft stills copy the clip to `public/`. Location: `YS_MANIM`, `YS_LATEX_BIN`, or `.data/tools/manim-venv` + MiKTeX (README). The Manim call is faked in tests (`BoardRun`).
- Sound effects (`video/src/sfx.ts`, `@ys/video/sfx`): in the timeline stage (vector, `input.sfx !== false`) events are derived from the animations with the render's timings (kinetic word landing shares `kinetic-timing.ts` with GSAP, typewriter letters, counter ticks + bell, pop, slide_in/spin whoosh, draw_on pencil, Manim board); sounds are synthesized in code (seeded noise/sine, no API), mixed into one 24 kHz mono WAV track (`assets/sfx/<episode>/<hash>.wav`) and added as the `sfx` audio. Studio: switch in the new-episode form (vector only) and the overview; `setSfx` reopens the timeline and render (free). If animation timing changes, update the event extraction too. Idea from the kalem repo (frame-locked events).
- Background music (`video/src/music.ts`, `@ys/video/music`): synthesized in code in the timeline stage (every mode, `input.music !== false`), no API. Sections come from the shots' `vector.mood` (`musicSections`: consecutive shots with the same mood form one section, one shorter than 8 s joins its neighbour; non-vector shots are neutral); mood → tempo/chords/arpeggio/bass in `FEEL`; all sections share one key (major + relative minor, key chosen from the episode id), transitions are 2 s equal-power crossfades. Ducking is baked into the track (`speechRegions`: `speech`, else captions, else the voice tracks; short silences are bridged). Levels live in `MUSIC` (−25 dBFS between lines, −11 dB under narration; TTS measured at ~−16.5 dBFS); the render's loudnorm brings the final mix to −14 LUFS. One 24 kHz mono WAV (`assets/music/<episode>/<hash>.wav`), `music` audio, volume 1. Studio: switch in the form and the overview, `setMusic` reopens the timeline and render (free). Tests compare tracks as bytes (`toEqual` is very slow on big arrays).
- Vertical video (9:16) safe zone `VERTICAL_SAFE` (core/rules.ts: top 250, bottom 420, right 150 px; Shorts/Reels UI): captions sit above the bottom UI and away from the buttons on the right, name tags stay in the visible part of the canvas outside the button strip (`tagBounds`), the Manim board is scaled like the stage (`stageFit`, same formula for stage and board). Idea from the kalem repo.
- Publishing package (`package` stage, between render and review): the `packager` agent (fast tier, episode language) writes the YouTube title, thumbnail text, description, chapters (by scene id), tags and hashtags. Chapter times are computed in code from `sceneOffsets` (`chapterLines`: YouTube's rule, first at 0:00, at least 10 s apart, none if fewer than 3). `<episode>.youtube.txt` is written; `state.package` can be copied from the Studio overview. If the agent fails, the thumbnail is still drawn.
- Vertical Short (`short` stage, between package and review; `pipeline/src/short.ts`): the packager's `short` ({from, to, title}: consecutive scenes, inclusive) picks the range, the agent sees each scene's length (`sceneSec`). `shortRange` enforces the limits in code (over `SHORT.maxSec` 60 trims from the end, under 15 s extends forward without passing 60, a single long scene up to YouTube's 180 s; no or unknown pick → from the start). `shortTimeline` cuts visuals/voice/words to the range, 1080×1920, drops music/sfx; the stage regenerates them for the clip, copies the new audio into the render `public/` and renders `<episode>.short.mp4` (`state.short`). Skipped for vertical episodes and `input.short === false`; errors don't fail the stage. Toggling captions/sfx/music reopens `short` too; `setShort` reopens only `short`. Studio: player, download (`?short`), title in the package card. In vertical frames `contentFit` shrinks the stage per wide shot so kept characters/props are not cut (not for close-ups, maps or Manim boards); `tagBounds` takes that fit.
- Thumbnail (`video/src/thumbnail.ts`, `Thumbnail.tsx`, composition "Thumbnail" 1280×720): `<episode>.jpg` in the publishing package stage (`state.render.thumbnail`; a re-render keeps the record, the thumbnail stays valid unless the package stage is reopened). Shot from `thumbnailShot`: a full vector scene with people and objects (maps rank lower, ties go to ~40% into the video), otherwise the middle still, none for clips only. Title is the package's `thumbnailText`, else `thumbnailTitle` (shortest meaningful part of a split title), never uppercased (the Turkish rule turned the English brand into "MİCROSOFT"); placed opposite the people, bottom centre if people are on both sides. The shot's own texts are not drawn. Errors don't fail the stage. Studio: video poster and download (`?thumb`).
- ffmpeg/ffprobe calls go through `runMediaTool` (`@ys/video/tools`): if they are not on PATH it falls back to Remotion's copy (when Studio was started from a terminal with an old PATH, voice-over failed with `spawn ffprobe ENOENT`); that copy has no fps filter, so clip normalization doesn't fall back and fails with a clear error.
- In the vector keyframes stage, while objects are being drawn, the still of a shot whose assets are all ready is extracted right away (`vectorPropsDraw(state, true)`, one sequential render chain, stops after the first error); an error that stops the stage does not preview that object's shot. The draft review / final preview refreshes them all.
- Re-create with a note (Studio → Shots, vector, before or after the render; user request 3 Nov): `replanShots` writes the note per scene of the picked shots plus their review findings (`review`, else `draftReview`, numbered by position in the scene; with findings the note is optional, so "Select weak shots" (score ≤ `DRAFT_REVIEW.badAtMost`) + Re-create fixes in bulk) (`state.replans`, a second request is appended) and reopens from keyframes; the keyframes stage then runs only `userReplans`: the director re-plans those scenes with the note, the current plan and the pointed-at shots (`replanScenes` feedback; an existing prop id keeps its old drawing, so a changed look needs a new id), then `restageMissing` and previews; the replanned scenes' old review entries are deleted. - Studio jobs run as a CLI child process whose output is read from a pipe; the job must survive Studio closing: the CLI swallows broken pipes (EPIPE) (`apps/cli/src/pipes.ts`), otherwise it died silently at the first log line.

- **Quality gate and realism are mandatory:** no SVG is used unchecked (`designAsset` → `gateCheck`: blind guess + `assetGate`, thresholds in `core/rules.ts`; the Studio Rules page shows the same constants). Real subjects and every object are drawn from images found online (Wikipedia/Commons) (`pipeline/src/reference.ts`). To change a threshold, change only `QUALITY_GATE`. Before drawing, `assetPlanner` looks at the references, fits the description to the asset type and writes a plan (`<key>.plan.json`, once); the designer draws to the plan, the gate looks for the plan's cues. The plan can't change the object's type (a magazine cover stays a magazine, the picture on the cover is drawn inside it); the original request also goes to the gate and type drift scores low (`gateDescription`). If the planner says the references don't show the subject (`referencesMatch: false`), the search is redone with its `betterQuery`; without a query, unrelated images are not sent to the designer or the gate. Likeness (3 Nov, user's "Daedalus Photo Analysis Prompt v1"; the gate's fidelity for real people averaged 6.1/10 over 115 characters, defects named hairline, hair texture, glasses shape, build, brows): for a character with references (realism on), after the planner has validated them, the `likeness-analyst` agent (fast tier) measures the visible form once (`core/src/likeness.ts` `Likeness`: scaled leaves 0–1 with confidence, enums, hex colours, up to 5 distinctive features; 0.5 = typical adult). Its rules are kept: no names, no inferences beyond form and colour, a possible minor is rejected; black-and-white photos and engravings give no colours. The person's name is not sent, only the cast description to pick the subject in a group photo. Stored per subject at `likenessKey(query)` (`library/likeness/<hash>.json`), so other styles and episodes reuse it, rejections included. `likenessBlock` (designer; only confidence ≥ `LIKENESS.minConfidence` and at least `LIKENESS.distinct` from typical, colours at ≥ `colorConfidence`) and `likenessCues` (gate: distinctive + hair, facial hair, glasses, headwear, build via `gateDescription`) turn it into text; the untrusted-library re-check passes the stored record to the gate; `ensureFigure` gives the sheet to the figure designer (looked up by `check.query`). A failure or rejection logs and the drawing goes on without it.

Offline → land, markers and routes only (key carries the data version). `historyCredits` adds the attribution line to the package description. When adding a new "factual" asset type (logo, monument, building…), look for a real data source first.

- Version: the single source is the root `package.json`. `pnpm release [patch|minor|major] [--publish]` (main, clean tree, typecheck+test, CHANGELOG, tag; nothing leaves the machine without `--publish`). - Every agent call starts its own Claude Code child process: at most `YS_CLAUDE_CONCURRENCY` (default 4) run at once per process; if the child crashes (`process exited with code …`, 0xC0000409 on Windows), the API returns overload/rate limit/5xx or a network error (`is_error` + `api_error_status`; network errors have no status code and are recognised from the text), no result message arrives, or `YS_AGENT_TIMEOUT_MS` (default 10 min) passes, `runStructured` retries twice; the cost of failed attempts is added to the result. The model's own errors (turn limit, schema) are not retried. The child is isolated from the user's ~/.claude (`ISOLATION`: no setting sources, strict MCP, claude.ai connectors/plugins/skill sync/hooks off, auto memory off, `verbatimPrompts`). - Quality-gate economics (31 Oct production data): an asset rejected in an episode is not redrawn automatically on resume/restart (a new drawing is a human decision: reject in Studio), and a rejected object is not offered to the director (`vectorProps[id].rejected`). Key props are the exception (3 Nov: the BASIC teleprinter, the Gural plate and the DNA X-ray were planned in 14, 12 and 7 shots, failed the gate at 5–6/10 and silently vanished from every one): a prop used in at least `QUALITY_GATE.keyPropShots` shots that is rejected is drawn once more from a simpler, iconic brief (`ICONIC_PROP` appended, same reference search, new key, `vectorProps[id].retried` so it happens once per episode; it still has to pass the gate); if that fails too, `restageMissing` replans the scenes that used it with a note per shot ("could not be drawn, stage it without it, drop gestures that need it") through `replanScenes`, shared with the draft review. A redraw builds on the previous attempt (`previous`), viewer guesses accumulate; if the first two attempts score below `QUALITY_GATE.hopelessAtMost`, no third is drawn. The gate is given the channel's style and palette (a colour the palette forces is not a defect). The draft review replans only the worst scenes (`DRAFT_REVIEW`). Expensive intermediate results survive a failed stage: `scriptDraft`, `shotPlanDraft` (with a fingerprint of their inputs; deleted when the stage finishes).
- Animation lint (`packages/video/src/lint.ts`, `@ys/video/lint`; 3 Nov, user: "zero errors, no meaningless errors in SVG and animation; recreate scenes when needed"). `shotModel`/`shotFrame` (Vector.tsx) are the pure halves of `VectorScene`; render and lint share them (`shotModel` takes the shot length `dur`). `lintShot` samples every `LINT.step` frames plus the last: face_cut (a still person's face 8–70% in frame at the first/last sample or in over `LINT.faceCutShare` of them; a face crossing the edge during a zoom or walk is normal), face_covered (a later drawn visible layer over >40% of the visible face; not while either moves), text_on_face, walk_through (same depth, one moving, on screen), pose_snap (a joint turning >25° between two consecutive frames; startles `FAST_GESTURES` and front/side drawing swaps excluded), empty_frame (visible layers <2% of the frame mid-shot; a lone person in a room is fine), missing_asset (layer/background not drawn), plus staging problems. Every issue has `replan`; false means code fixed it without losing meaning. Staging (`staging.ts`, inside `shotModel`, before/after layout): reading/show with nothing held takes the nearest portable prop (`PORTABLE_M`, within 1000 px, not a surface/base) else drops (replan); overlapping arm gestures (≥ `CLASH.sec`) are sequenced (the earlier ends at the later's start, else the later starts after it, else drops); burst gestures are capped (`BURST`: cheer/wave 3.5 s, surprised 2.5 s; PHP s4-sh6 had two people cheering for 13 s); point with nothing to aim at becomes explain (the rigPose no-aim fallback is unreachable); typing/writing whose hands (`workZone`) touch nothing drops (replan); a character on a character (riding) is unsupported (replan). Layout (`core/layout.ts`): a standing worker steps to the near edge of the nearest hand-height thing within `WORK.reach` (`toWork`, before `converse`, which keeps workers anchored); a person walking/sliding through someone's standing spot at the same depth moves `PASS.depth` forward (behind if at the camera) (`passBy`, before resolution); grounded furniture in front hiding a face: a standing person steps aside (not behind a person in front), a sitting person's furniture is lowered up to `FURNITURE.lower` (things on it move down). Camera: `faceSafe` (last pass; close-ups may shift vertically, wide shots only horizontally) moves the focus least so every still face (rest pose, padded `FACE_SAFE.pad`) is fully in or out at both ends. A person whose face is out sideways must not leak a body sliver either (their box widened by `FACE_SAFE.arm` for a pointing arm is fully out, or the face comes in; 4 Nov bench: 17 of 133 close-ups showed only an arm or a strip of a person, now 2); a face out at the top (hands at a desk) is left alone. Motion: rise/fall last at least `GESTURE_TRAVEL[type] / GESTURE_SPEED` (`gestureTimes`), and spontaneous gestures fade by a continuous weight (gait, `nearness` to a walk, arm gestures): boolean toggles made joints jump 25–70° in a frame (275 of 923 shots). Cheer: IK fists pump between `CHEER.pump` and `CHEER.high` with elbows out, per-person tempo/phase (`cheerPhase`, shared with the body bounce); the old ±150° arms with 15° elbows read as stiff sticks and everyone pumped in sync. Clap: palms meet at `CLAP.meet` by IK with foreshortened forearms (`CLAP.fore`); the old fixed angles crossed the hands on the chest. Desk work (`DESK_WORK`, user: "looks like rubbing hands at the keyboard"): typing wrists sit on the two halves of the keyboard by IK (~66 px apart, foreshortened forearms), fingers down-in at a fixed absolute angle, a tap dips the wrist `dip` px and the hands drift across the keys; the old fixed angles put both wrists on one point (200, 431) and turned the hands opposite ways on every tap. Writing: the pen hand moves along a line on its own side and returns during the pause, the other hand holds the paper; the old pose crossed the arms. Pipeline: the keyframes stage runs `lintRevise` after `restageMissing`: scenes with visible defects are replanned once with per-shot notes (fixed ones prefixed "code fixed:"), most defects first, at most `ANIMATION_LINT.maxShare`; results go to `state.lint`; a lint failure logs and continues. Audit on the existing 923 shots: pose_snap 275 → 0, face_cut 21 → 2, action_without_prop 15 → 3.
- Anatomy (`video/src/anatomy.ts`, 3 Nov, user: "nothing against human anatomy; use a JS library if one does it"): no maintained JS library has human joint limits (the IK ones, inverse-kinematics, ikts and closed-chain-ik, are iterative solvers without anatomical data, last released 2022–23), so the limits are ours, from AAOS range-of-motion tables (`ANATOMY_FRONT`/`ANATOMY_SIDE`, `SHOULDER`, `ELBOW_FLEX` 150, `STRETCH`). `motionOf` clamps every `rigPose` output with `anatomical(pose, profile)` (side limits for the walking profile / 3D turn) and puts the clamps on `Motion.strains`; lint reports them as `anatomy` (`replan: false`). Angles wrap (`fitAngle` tries the equivalent nearest the range centre and returns in the input's window). The front-view elbow is measured in 3D: each segment's foreshortening (`sy`) gives its depth and `flexion(s1, s2, φ)` takes the most plausible reading (both toward the camera); `maxPhi` is the projected bound. The shoulder crosses the body `SHOULDER.inward` (50°) at full length, plus `reach × depth` when the arm reaches toward the camera, and goes `over` (195°) above the head. Visible length is the part's `sy` times its carrier's (shin × thigh, hand × forearm; the forearm's CSS undoes the upper arm's); face parts are not limited. Measured on 969 shots / 34k pose frames: the only real violation was the think chin pose (elbow folded 158° in 381 frames of 5 episodes when the chin sits near the shoulder); the forearm now also reaches toward the camera until the 3D flexion is at most `THINK.flex` 140 (forearm ≥ `THINK.fore` 0.6). A vector-scene test sweeps every gesture × 6 seeds × plain/mirrored/holding/sitting, every gesture pair and every gesture while walking (side SVG and 3D figure) and requires zero clamps. 3D figures (`poseFigure`) turn a foreshortened forearm or thigh toward the camera (`PITCHED`; lower part Rx(undo parent)·Rz·Rx(own) as a quaternion) instead of squashing it; the shin's visible length carries the thigh's (`CARRIED`), so a seated figure's shin hangs full length.
- Eyebrows (`video/src/browShape.ts`, 3 Nov; frame inspector: "face not worried" in 40 of 955 reviewed shots, "calm, not angry", "neutral, slight smile"): the brows group could only slide up and down, but emotion reads from the brows' tilt. `splitBrows` (cached per asset by `browsFor`) splits the drawing's own `brows` group into `brow-l` (screen left) and `brow-r` groups: its direct children, or a single path's subpaths (paper.js, absolute path data; the duplicated id is dropped), are assigned by their centre against the middle of all brows; it returns the groups' centres as CSS pivots. 130 of 149 library drawings split, every front view (the rest are single-brow side views and empty groups). `EXPRESSIONS` has `inner` (degrees the inner ends rise: worried 20, sad 15, happy 3, surprised 4, angry −18) and `knit` (px toward each other; angry 2.5); `innerUp` turns brow-l counterclockwise / brow-r clockwise. Thinking (`quizzical`, `QUIZZICAL`): one brow (seeded) rises with its outer end arched, the other drops slightly; the think gesture adds it unless the expression already does; shake_head knits the brows. The render writes brow rules only when the split worked (side views, 3D figures and unsplittable drawings keep the whole-group motion). 3D figures have `brow-l`/`brow-r` groups at ±27 px so the same pose tilts them. Known limit: a drawing whose brows touch same-coloured hair loses them in the hair when raised (surprised).
- Pronunciation (`pipeline/src/pronounce.ts`, `agents/src/pronounce.ts`; 3 Nov, user: Gemini TTS read "C++" in Turkish narration as "si artı artı"). A TTS voice reads every word by the narration language's spelling, so foreign names, brands, abbreviations and symbols came out wrong. The voice stage sends the TTS a respelled text (`sayPlan`): the built-in `LEXICON[lang]` (common tech terms; case-insensitive whole words, a suffix after an apostrophe is kept: "C++'ın" → "si pılas pılas'ın"; multi-word names match as a whole, longest first) plus `state.pronunciations` (the cheap `pronouncer` agent's finds, one call per voice run; it never overrides the lexicon or a hand edit, and a failure logs and continues with the lexicon). Word timings (provider timestamps, or `alignWords` on the spoken text) map back to the written words by letter position (`restoreWords`): captions keep the written form, a respelled word carries `WordTiming.say`, which visemes and speech beats use; `SceneVoice.spoken` keeps the text sent to the TTS. Existing voices are not redone automatically. Numbers (`pipeline/src/numbers.ts`, 4 Nov, user: "the Turkish wording of numbers can be comic"): the screenwriter and script doctor used to be told to spell numbers out and wrote "Intel 4004" as "Dört bin dört" in the captions; now `NUMBERS_AND_NAMES` tells them to write digits in the language's conventions and keep names in their original spelling, and `sayPlan(text, terms, "tr")` reads what the lexicon did not match: ordinals ("II. Mehmed", "19. yüzyıl", numbers up to 20 before a capital: "1. Dünya Savaşı"), decimal comma ("1,5" → "bir buçuk"), thousands dot, versions after a name ("Python 3.12" → "nokta"; a following "milyon" makes it a decimal), %, currencies (moved after "milyar", suffix re-harmonized: `harmonize`), "10x" → "kat", ranges → "ile", fractions ("dörtte üç"), times, "64-bit", "GPT-2", MÖ/MS, ≈/~, abbreviations (`sayAbbreviation`: the dot is dropped before a lowercase word or after a title). The writer's suffix after the apostrophe is kept ("1453'te"). A number inside a name said differently (a chip) comes from the pronouncer, which is told not to list plain numbers. Abbreviations read out in full (4 Nov, user: "TBMM should be Türkiye Büyük Millet Meclisi"): the lexicon has TBMM, ABD, AB, BM, SSCB, TDK, MEB, THY, TCDD; the pronouncer expands context-specific ones (CHP…), keeps acronyms said as words (NATO, TÜBİTAK) and spells the rest (PTT). The writer's suffix matches the letter reading ("ABD'ye"), so for an all-caps term expanded to several words `attachSuffix` rebuilds it: pronominal n after a compound ending in a possessive ("Devletleri'ne", "Birliği'nden", instrumental "Meclisi'yle"), no buffer after a consonant ("Milletler'e", "Milletler'in"), vowel harmony.
- Concept/asset flows are tested end to end with a fake Claude in `pipeline/test/concept-flow.test.ts` (each agent is recognised from the fields of the schema it asks for). When `designAsset`/`vectorConcept` change, add a scenario there.

## Rules
- **Cost first:** a new provider must have `price` and `qualityPrior`. Cite the price source in a comment. If there is a local (ComfyUI) option, prefer it.
- If you are not sure about an endpoint or field names, add the spec with `verified: false`.
- Code comments are Turkish; the Studio UI is Turkish + English (from the dictionary). Pipeline log lines and user-facing errors are written with `msg("log.…"/"err.…")` + `LocalizedError`, their texts live in the `core/src/messages/` catalogue (TR + EN required); Studio shows the selected language, the CLI prints Turkish. - After every change: `pnpm typecheck && pnpm test`. Test coverage is 100% (lines, branches, functions, statements; threshold in `vitest.config.ts`): new code comes with tests, and `pnpm test:coverage` fails if it drops. No real network/Claude/Chrome/ffmpeg in tests (fake `fetch`, `queryFn`, `vi.mock`). - When editing files with a script, never pass text containing `$` as the replacement string of `String.prototype.replace` (`` $` ``, `$'` and `$&` are replacement patterns; this once pasted a copy of the whole file into a note). Use the Edit tool or `split(a).join(b)`.
