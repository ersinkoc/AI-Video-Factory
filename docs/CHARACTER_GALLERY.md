# Character gallery in new episodes

Choosing **Vector drawing** in the new-episode form now opens a visual character gallery above the style examples. It uses the existing approved, reusable character bank. Characters without a currently supported style pack remain outside the new-episode selection contract, as before.

Each card shows the actual character, name, role, style/line style, description and prior episode count. A stored 3D figure preview is preferred when available; failed figure images fall back to the SVG. A missing preview has a readable placeholder without discarding a valid character record. Original art is not redrawn or regenerated by browsing.

Use a card's presenter button or cast checkbox. A presenter cannot also occupy a cast slot. The gallery permits one presenter and at most five additional cast members, matching the existing episode request. Selected characters stay visible in the selection strip even when their cards are on another page or hidden by a filter; remove one there or clear the whole selection.

Search covers names, roles, descriptions, IDs and mascot series. Turkish case and diacritics are folded for searches such as `isik` matching `Işık`. Style and line-style filters combine with search. **Only styles matching the selection** narrows the gallery to compatible assets. Clearing filters preserves character choices; clearing the selection releases its style constraint.

The episode uses the selected characters' shared style pack and line style. Incompatible new choices are disabled and explained instead of allowing a mixed selection that the server would later reject. Clear the selection to change to a different character style. Existing backend validation remains authoritative.

The gallery displays twelve cards per page, with result counts, page position and previous/next controls. Pagination is client-side over the metadata already loaded by the new-episode page; only the current page's character cards/images are mounted. It is not a new server-side catalog index. Searches and filters reset the page; presenter/cast state remains independent of pagination.

The empty state links to the existing character-bank management page. Browsing, filtering and choosing characters makes no generation call. Creating a new character remains a separate action on that management page, with its existing cost disclosure. Episode creation still submits the same `presenter` and `bankCast` IDs, only in vector mode.
